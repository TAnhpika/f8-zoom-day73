# Route handler

Xây dựng các endpoint API

- Sử dụng 1 số tính năng đặc biệt của Next: Set cookie http only, revalidate cache,...
- Web hook để xử lý thanh toán

Cách xây:

- tạo route.js api/users/
- chứa các hàm tương ứng với các HTTP Method: GET, POST, PUT, PATCH, DELETE
- muốn nhận response dùng NextResponse

- gọi api ở: localhost:3000/api/users

- Post: muốn gọi body dùng async vì body là 1 promise

- Route handler: muốn có 1 endpoint rõ ràng theo methods (GET, POST,...) / viết endpoint để bên khác xử dụng (web thanh toán / trang admin dùng react, trang user dùng next có cache fetch. Khi trang react muốn thêm dữ liệu vào BE thì xóa cache -> gọi API sang Next để xóa -> Next cần viết API để react gọi sang khi muốn cập nhập)

## Cookie

- cách set về httpOnly
- set ở server action / route handler / proxy (middleware)
- dùng route handler vì nó chạy ở server

- trong các server component chỉ đọc đc, k set (xóa, sửa) đc
- client muốn lấy cookie thì nhờ server lấy hộ
- muốn set cookie = route handler -> phải gọi end point API từ client, gọi từ Server k đc

- bản chất của cookie là trả về response header cho trình duyệt. Gọi trên server k trả về đc vì nó chỉ trả về html

# Server Action (Server function)

- Hàm chạy trên server (Có thể gọi ở bất kỳ đâu)
- Tác dụng: Xử lý 1 số tính năng đặc biệt của next: cache, cookie
- Ngữ cảnh: Thường áp dụng trong các trường hợp mutation (thêm, sửa, xóa), xử lý form

- Gọi ở client thì phải tách file, gọi "use server" ở đầu
- Gọi ở server thì có thể gọi inline
- dùng cho xử lý auth (nhanh, gọn hơn route handler)

Implement:

- "use server"; // kích hoạt server function
- dùng formData.name để get
- cần tách action "use server" sang 1 file riêng

Inline action - đưa "use server" vào thẳng RSC
Nhược điểm Inline action:

- k xử lý đc thông báo vì đang ở server component, k tạo state xử lý thông báo đc -> dùng cho các form đơn giản k cần thông báo
  -> tách ra file riêng r import vào client component
  -> có thể xử lý thông báo
